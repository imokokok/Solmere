## 实际窗口操作

通过 Windows 原生鼠标操作导出的 `AfterHoursKitchen.exe`，窗口客户区约 960×568：

1. 支架取锅盖，快速移到锅口松手，观察先抬起转正、再落座；锅没有被推离炉位。再拖回支架，锅盖没有甩出屏幕。见 `native-lid-seated.jpg`、`native-lid-returned.jpg`。
2. 从冰箱取鸡蛋，一次移到锅口开壳，两半蛋壳落到旁边；中火下蛋白变白、蛋黄凝固。
3. 同场从冰箱取土豆、完整落刀，实际形成两片；抓住一片将同份两片一起送入锅口前部。锅位保持，菜板上不残留同份切片。前一导出包的近沿复现见 `native-cut.jpg`、`native-batch-in-pan.jpg`；最终厨房代码的同场结果见 `native-cooking-and-tools.jpg`。
4. 黑色锅铲从筒里取出，松手留在锅边，再取起归筒；最终截图包含已经归筒的工具。观察取出、松手、归还三个状态。
5. 关火，点击实体盘子进入装盘工作台，确认实际有三块食物（蛋一份、土豆两片），全部装盘后把真实照片加入 DIY 菜谱。输入菜名、保存、关闭 EXE 并重启，菜名、实际用料与照片仍在。
6. 这个流程额外发现贴纸快速拖动不生效，修复后重新导出 EXE。打开刚才保存的同一张菜谱，移动爱心贴纸到空白处，用画笔划线并保存，缩略页同步更新。见 `native-recipe-edit.jpg`、`native-recipe-saved.jpg`。
7. 最后补查左侧海盐：从柜格快拖到锅上方，再快速点回原位。旧版瓶子掉在台面；最终重导出包沿同一路径正确显示“已放回海盐，保留原来的物品和余量”，见 `native-salt-return.jpg`。

最后补查发现调料在快速点回原位时会提前掉落；修正后再导出。在最后 EXE（SHA256 见 RELEASE.json）上又重新做了一遍：鸡蛋开壳、中火凝固、关火、土豆切两片、整批入锅、实体盘子装三份、照片放进菜谱并快速拖动。证据为 final-cut-batch-and-egg.jpg、final-plated-three-portions.jpg、final-recipe-photo-fast-drag.jpg；保存重启链沿用前次同代码验证。不把截图称为完整录像。文字录入通过自动化文字注入完成，**不是 Windows IME 候选窗验收**。原生控制接口仅提供瞬时点击/拖动，没有持续按住功能；持续撒粉/倒酱由引擎输入测试验证，没有冒称原生窗口长按出料已验收。

## 性能与声音

`performance.json`：RTX 4050 Laptop / Godot 4.7.2 Compatibility，48 个真实切块，24 在菜板、24 在锅中接触。冷态 600 帧 P50 27.376 ms、P95 35.633 ms；热态 300 帧 P50 36.078 ms、P95 55.204 ms。初次冷态 P50 135.251 ms、P95 163.1 ms，相关旧/新日志均保留。不是稳定 60 FPS 承诺；热态仍有尖峰，其他桌面应用保持打开。

`kitchen-audio.wav` 为实际 Godot 混音输出，48 kHz 双声道，约 36.36 秒。`audio-mixer-audit.json` 对 16 个事件区段检查峰值/RMS，静音区段单独检查，0 削波。录音隔离测试窗口切换引起的自动静音，生产失焦逻辑另有回归。脚本为 `tools/audit_mixer_capture.py`（需要 NumPy）。**客观非静音输出不代表人耳逐项听感已验收。**

## 失败与限制

`reproductions/` 保存修复前实际失败日志：锅盖放置、归架后旧位置覆盖/挡刀、海绵漏吸水、拼贴漏最后位置和盐瓶快点归位。初次远程提交 `33f72a7` 的 51 个 Godot 脚本全部通过，但素材清单原始哈希受到 CRLF/LF 差异影响；现在只对 JSON 换行规范化，所有原画和显示图仍逐字节校验，另测内容变化与图像变化必然失败。它们是历史复现，不是最终通过结果；没有删掉断言来把检查改绿。早期 QA 图片扩展名错误属于验收工具问题，已更正并用 `.gdignore` 排除 QA 资源导入。

物理仍是 Godot 原生 2D 刚体加受限抓取、有限体积水流和热/材质游戏模型，不是完整流体、软体和化学模拟。全部材料的主观手感、长期任意组合、系统 IME、人耳听感和低配性能仍不能由这些检查证明。完整实现、取舍、来源许可和逐项根因见 [本轮详细报告](../../docs/PHYSICS_AND_GAMEPLAY_ROUND_REPORT_20260929.md)。
