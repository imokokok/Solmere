# 厨房文字排版反馈落实 · 2026-09-27

本轮依据用户附图反馈：一页内要能看出哪些文字属于同一组，同一层级不要混用圆点与斜线作为分隔。附图是用户指定的反馈参考，不把图片中的其他陈述当作独立任务。

## 已实现

- 欢迎页分为“今天可以做些什么”“营业与练习”“先记住这三个动作”，用区块标题、组间留白与统一圆点列表展示。
- 操作说明按取材、切配、火候、招牌作品和清锅分成五组；组内每项只讲一个动作或限制。说明区滚动，返回厨房的按钮保持在滚动区外。
- 展开订单分为客人的需求、点菜、口味与习惯。需求原文和所点菜谱保持完整；未知偏好仍不显示。继续使用现有纸纹与 WenKai 字体，正文为 22 px，区块标题为 24 px。
- 顾客反馈分为评价、具体感受、餐前餐后、本单账目和回复。详细理由按原数据的换行逐项显示，未改动评分或结算算法。较长页面在内容区滚动，继续招待和写入菜谱的入口留在外面。
- 厨房手记将材料、编号做法和备注分组。每个步骤的示意图、标题和正文属于同一行组；菜谱左页仍与书架共用原始纸页渲染。
- 回信列表区分客人的话和自己的回复；收班页区分今日账目与招待人数。系统文案里同类信息的圆点、斜线串联改为列表、标题或正常标点。
- 共用排版函数使续行与正文左边缘对齐；圆点独立于正文，使用 `SIZE_SHRINK_BEGIN` 对齐第一行。段内间距 8 px，阅读滚动区内组间间距 20 px，另有 8 px 组尾留白。

实际能力的双操作按钮“暂停 / 帮助”“丢弃 / 清理台面”和页数、步骤数中的数值比例仍保留其功能含义。用户已保存的自由文字与纸面图层没有批量改写；菜谱模板的新默认提示统一使用正常标点。

## 验证证据

最终记录在 [文字排版 QA](../qa/20260927-text-layout/README.md)。最终完整入口 44/44 Godot 脚本、工程导入、120 帧启动与录音审计全部通过，0 失败步骤。真实 Godot 4.7.2 图形渲染的 17 张截图覆盖欢迎、操作说明首尾、完整订单、菜谱、反馈首尾、回信和结算；其中八张验证缩小窗口。所有面板均在 1600×946 的逻辑视口内。macOS 对实际窗口尺寸作了限制，两组 PNG 实际为 1440×851 和 1150×680，捕获日志逐张记录像素尺寸，不能称为原生 1600 像素截图。

截图脚本是生产页面的独立样例，使用随机独立菜谱路径，并在捕获子类中关闭反馈读取和写盘。评分样例通过现有 domain 评价函数生成；不是一次完整人工营业或玩家真实反馈。既有系统鼠标长期试玩、Windows IME、所有 DPI 与人耳验收的边界沿用原记录；本轮没有重新导出 Windows 包。
