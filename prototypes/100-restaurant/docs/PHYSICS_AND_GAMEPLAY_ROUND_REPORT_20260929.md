# 街角厨房：物理交互、材质反馈与整体质感重构报告

日期：2026-09-29。范围从用户提供物理重构规格书后的 2026-09-27 工作开始，覆盖本轮 2D 美术、操作、厨房事故、火候提示和 Solmere 正式入口。本文区分此前已合入的基础与本次新增修改；具体发布提交、运行包和检查结果见 [最终自检证据](../qa/20260929-precision/README.md)。

## 一、这一轮到底改变了什么

目标是让玩家能从动作判断结果：东西拿出来就离开柜格，落下会受承托，切开仍是同一份食材，油、水、酱和火候会留下不同变化。视觉上的厚度、实际碰撞、声音和菜谱记录应当描述同一件事。

这不是更换一套引擎名称。本项目仍是 **Godot 4.7.2 原生 2D 刚体系统**，加上已有的 MIT GodotSpringDamper 辅助、项目自己的有限体积水量与简化热反应模型。没有接入 Rapier，没有启用三维 Jolt，也没有把取消的三渲二实验混入正式版本。

本轮主要成果：

1. 把锅、盖、食材、铲勺的搬运改成有限抓取力和接触驱动，取消整批冻结搬锅与固定爆盖轨迹。
2. 修复柜格扣库存、拖拽误归位、锅柄抢点、工具镂空点不到、工具放下消失和锅翻倒后难以恢复。
3. 串起食物受热、两面变色、中心熟度、融化、吸水、挂酱、残味以及照片/DIY 的状态。
4. 让水从接满的锅沿流出，再经过台面、水槽和地面铺开；增加差异浮力、浸水色调、跳闸与恢复。
5. 增加有条件的油火、烟、油水飞溅、纸屑散落、肥皂泡与软质外观反馈。
6. 保留团队原画，统一补充食材，修边、校准落脚与遮挡，简化纸页和底部导航。
7. 将无意义的“绿色完成条”换成锅温指针与建议区间，并显示融化、未熟、焦化、积汽或起火的实际原因。
8. 正式从 Solmere 饭店入口进入这一厨房，按真实出餐和工作时间结算，并保护存档事务。

**“成熟游戏”不应仅用功能数量判定。** 这轮优先减少误操作与状态矛盾；完整人耳试听、系统 IME、长时间自由组合、首次玩家可理解性仍需人工测试。自动化结果不代表这些主观与开放式体验全部合格。

## 三、引擎和物理模型

### 3.1 原生刚体负责什么

重力、碰撞、速度、角速度、转动惯量、摩擦、回弹、休眠、容器承托由 Godot 2D 求解。采用 120 Hz 物理步、16 次求解迭代，快速物件使用形状 CCD。工具和锅不是逐帧把位置写到鼠标坐标，而是追随有上限的抓取力与转矩。

这带来三种可以理解的差别：重瓶跟手较慢；快速甩动保留部分动量；圆润完整食材比切块、湿软料更容易滚动。为避免一动就失控，手持物体角速度限制在约 ±3.8 rad/s，翻拌冲量、接触触发频率和返回辅助也有边界。

| 对象 | 当前处理 | 目的与限制 |
| --- | --- | --- |
| 瓶罐 | 包装自重＋剩余内容物质量；局部抓点、惯量与瓶口方向共同影响出料 | 满瓶和空瓶不一样；不是每种塑料/玻璃都做完整弹性材料模拟 |
| 整件食材 | 材质表驱动回弹、摩擦、阻尼；近圆形完整食材有适量滚动 | 不再统一按同一块石头处理 |
| 切片、切块 | 独立多边形、独立质量与热状态；默认一起拿起同一份，Shift 取单片 | 菜板透视平面保留稳定支持，不是假装全三维桌面 |
| 木铲、黑铲 | 不同质量、自然操作角度、扫过食材产生有限翻拌冲量 | 盖上锅盖时不穿盖炒菜 |
| 木勺 | 三段组合碰撞体承托，勺内残酱可转移 | 勺底不是磁吸中心；视觉勺沿不再额外画出裂缝般的空弧 |
| 锅 | 空心复合碰撞体、锅沿与容量；内容物保留接触 | 用颠锅造成实际腾空，音效不负责把食物弹飞 |
| 锅盖 | 独立刚体、漏汽、积汽、接触和蒸汽冲量 | 无“必定一整圈”剧本；压力字段为游戏代理值 |

### 3.2 操作容错与物理感的分寸

- 快速取物使用按下事件的坐标建立抓点，避免输入排队后用最新鼠标位置导致偏移。
- 松手时若物体尚未追上手，会有限延续靠近目标；超时后释放，不无限悬空跟随。
- 归柜同时检查手的释放目标和实体位置。轻轻转瓶不会因瓶身仍在原位附近而误归库存。
- 工具放下保持在外面。放回筒口才进入约 0.65 秒的缓动目标，沿最短角度回正，实际落稳后播放轻接触声。
- 木铲镂空附近提供 4 像素选取容差；透明矩形角落和藏在筒里的柄仍不抢邻近工具。
- 锅盖在锅口附近释放即可获得有限的对位辅助；不是必须像素级严丝合缝，也不是瞬移贴上。
- 空手按 **R** 可缓慢扶正锅并放回灶台；越出工作区时也有恢复路径，避免拖出画面后永久丢锅。
- 背后盘堆有可用取盘区域，对应现有实际盘子，不伪造无限生成的盘子。

## 四、食物状态：从切配到照片保持连续

### 4.1 切菜

刀线与实际多边形相交决定切片位置和质量比例。切块保留原画 UV 和比例，不把每个小块都重新拉伸为一整张食材图片；只有切开的内缘显示切面厚度。退化或过窄多边形会被筛掉，避免渲染裂线和无效几何。

新补充切面包括扁平手绘内瓤与六格食品切面：芝士、面包、豆腐、香肠、卷心菜、玉米；可共享的蓝纹芝士、臭豆腐使用对应基础切面。原有切面继续保留。**这不等于每一种食材、每个角度都拥有完整组织学切面**；实际部分切割由几何完成，贴图补足内部外观，未以十张预制整体图片冒充任意刀切。

菜板固定。完整圆料、薄片与软料的落板滑动与停止不同；离开菜板后恢复自由刚体，切片不会永久直挺挺地站住。

### 4.2 受热与食材差异

每个实体保存两面温度、中心温度、熟化量、两面褐变和焦化、含水量、软化、转化液体和翻动历史。锅接触面与暴露面升温不同，相互接触的食材可交换热量；上层不会永远保持室温，也不视为直接贴锅底。

| 材料 | 可观察变化 | 状态依据 |
| --- | --- | --- |
| 芝士、黄油、巧克力 | 升温后摊软、化开，部分相变物可以挂到邻近食物 | 各自融化阈值、潜热近似和液体份额，不是统一计时变小 |
| 面条 | 水煮吸水增重、由直变软，拿起有弯曲、下垂与滴水外观 | 真实锅水扣减、吸水量和软度；丝状绘制不是完整绳索物理 |
| 蘑菇、叶菜、洋葱 | 软化、失水和不同程度收缩 | 材料含水量、厚度和软化参数 |
| 肉、蛋 | 中心熟度与两面变化；翻面改变接触面 | 接触与核心传热；游戏压缩参数不能用于现实食品安全判断 |
| 番茄 | 软烂并在搅动后出汁 | 软度＋实际搅动工作量，非一入锅就换成酱贴图 |
| 盐、胡椒、酱料 | 粉与液体不同出料，有限余量，接触后改变表面组成与颜色 | 实际流量、涂层数量与组分 |

敲蛋的第二次命中范围扩大，第一次已敲过的鸡蛋不必再次精确压在同一条窄线。破壳时暂时隐藏的蛋不会被前景代理重新画成完整鸡蛋。对应蛋黄/蛋白与切面、保存的回归仍保留。

### 4.3 挂酱与残味

番茄酱在落点附近形成有限红色挂层；酱油参与实际组成混合和褐色表现，翻拌促进接触与混合。液体不能凭空复制到所有食材上，转移会扣来源数量并增加接收方质量。锅残留、勺残留、食材、切片和清洁抹布都有可追踪的转移链。

抹布继续承担残味清理，而不是摆设；“清理台面”与“把锅洗净”不能暗中当作同一个动作。照片和 DIY 使用实际摆盘快照，保留热、切配、挂酱与形状，不能用一张漂亮预制成品替代玩家做出来的东西。

## 五、水、浮力与厨房事故

### 5.1 连续水路

水的唯一数量账本由 `water_runoff.gd` 管理。锅里的食物会占容积，水增加锅重；当前低沿容量受倾角、晃动和锅沿形状影响。接满后先形成沿口余量，再从真实位置下落，落向水槽或台面，经过 64×8 台面格与 64 个地面列渐渐铺开。移动锅不带走已经洒出的水。

新水龙头以现有手绘场景为参考生成，保留开关与接水功能，喷口和流出位置对应。水槽水面随实际容量上升，满后从前沿流出；用于遮住旧抹布的补片改为沿水槽斜边裁切，移除伸进池内的生硬方块接缝。

### 5.2 浮力与浸水

水面绘制、浸没深度、浮力和碰灯判定读取同一个平滑地面水面。面包、袜子、纸、彩屑等较轻物体更容易浮起；石头、肥皂等更容易沉下；空瓶与有内容物的瓶子不同。木勺/木铲与黑铲有不同浮力响应，正放锅可保留空气，倒扣锅的上浮能力更弱。运动附加水阻和转动阻尼，水下食物呈现柔和偏冷的色调。

这是按二维浸没深度与密度代理施力的游戏模型，**不是任意形状排水体积积分，不是完整流固耦合**。重力、受力与碰撞由原生刚体计算，视觉水位到升数的映射为压缩厨房比例。

### 5.3 失败应该有原因，也有恢复办法

| 事件 | 触发条件与反馈 | 玩家恢复 |
| --- | --- | --- |
| 水淹 | 持续进水超过容器与排水能力；先局部积水，再向两侧铺开，轻物上浮 | 关水、排水与擦拭，不是瞬间擦掉全屋水 |
| 顶盖 | 加盖沸腾，积汽、颤动，持续加热后产生向上冲量 | 减火、揭盖，泄汽后再盖；盖子靠碰撞落下 |
| 焦化 | 干热时间和表面温度累积，两面分别焦化 | 关火、翻面减缓；焦味不可逆抹掉 |
| 油火 | 高锅温、足够油或可燃材料、少水且未盖锅 | 关火、盖上锅盖，火烟渐退；不是绿条到头自动爆炸 |
| 热油遇水 | 高温油中出现新的水量 | 短促飞溅、下料声与有上限的物体冲量 |
| 跳闸 | 地面水上升碰到灯位置 | 灯光变暗、短火花、炉火关闭；关水退水后恢复供电，炉火不自动重开 |
| 肥皂泡 | 在锅内拿肥皂摩擦或工具接触推动 | 摩擦越多泡越多，最多 180 个；停止后约 2.5 秒缓退，随后快速消散 |
| 彩纸散落 | 松开完整彩屑材料 | 拆成最多 12 个独立轻质小片，继承并分配原质量/热/酱状态；有实体总量限制 |
| 袜子软垂 | 拿起、移动与落下 | 条带网格随运动摆动；碰撞仍用保守刚体外形，不声称布料求解器 |

事故的数量不是品质指标。本轮没有增加无因果的随机爆炸、无限生成食物或长时间永久遮住操作的特效。火和泡沫是状态驱动绘制，尚未实现完整燃料消耗、烟气传播与通用化学反应。

## 六、修正最新截图里的火候条和文字

旧条把“可生吃”当成“已经做好”，所以冷芝士也会一整条绿，且条与导航文字重叠。该进度条已删除。

新的底部中区单独容纳三层信息：**食材当前状态 → 此刻该怎么做 → 锅温指针与绿色建议区间**。菜单放到左侧，保留食材柜、菜谱、出餐、手记四个入口；删除同一位置的叠字。

| 场景 | 文字/建议 | 绿色区间的意义 |
| --- | --- | --- |
| 刚下锅的芝士 | “还没化开”，开小火、轻翻 | 小火慢化建议，不伪装成完成率 |
| 芝士已转化足够液体 | “已经化开”，关火装盘，避免粘底 | 读取实际相变份额 |
| 芝士和生鸡肉同锅 | 熟化判断仍检查鸡肉 | 融化配料不能掩盖主料未熟 |
| 水煮 | 煮开后小火，观察水量 | 换成煮的建议区间 |
| 跟做凉菜 | 不用加热 | 不要求把所有菜都烧熟 |
| 超过建议温度 | 提醒减火、可能焦糊 | 过热区表示偏离建议，后果由真实状态决定 |
| 高温油／积汽／实际起火 | 分别提示起火风险、顶盖风险、当前灭火操作 | 优先级高于普通熟度提示 |

温度带是游戏做法建议；它不会直接触发爆炸、强制判定熟度或修改锅温。菜谱启用时同时参考其保存的水量和热状态，避免冷番茄直接满足番茄汤目标。没有把所有玩家自由文字自动理解为精确温度曲线。

## 七、美术统一与空间落地

### 7.1 保留什么、修改什么

- 团队手绘原件保留原始字节，尤其保留用户认可的蘑菇轮廓、笔触和色块。
- 64 张补充食材使用四张单独标记的平涂手绘图集；不覆盖团队原画。原 Solmere 的香草、海豆、星盐按原字节接入正式采购映射。
- 103 张运行显示缓存带输入/输出哈希。透明边缘通过邻近实体颜色填充，减少黑白边；只有补充生成图集做小碎屑清理，去掉串入芝士格的邻格像素。
- 新锅与前沿蒙版共用同一张画和同一锅口几何；避免画两个不对齐的锅沿。水龙头和新切面保留生成提示词与 SHA-256。
- 被评估后不采用的原画重绘候选保存在仓库外，不当作已替换资产。

### 7.2 “在盒子里”和“贴在盒子前面”的区别

柜格位置根据有效透明轮廓的底部落脚，不使用整张大画布中心。调料台只有对应瓶罐，不放米饭；盐、糖、酱油放大到合适比例，避免部分瓶子过小。

库存物件底部受架子前沿遮挡，视觉支撑高度、命中区域与陈列槽共用几何；取出后先有短暂手持过渡，再进入前景。释放在冰箱前的食材仍在冰箱前落下，不穿到蓝色背板里。回柜是同一实体的缓动落座，保留余量，最后才交回库存显示。

冰箱改成可拖把手/滚动查看的空间陈列，取消冰箱页码；同种不同颜色蔬菜可跨不同陈列位置，不强求全塞第一页。奇物架仍有有限分层浏览，这不等于真实冰箱分页。

暖色环境光、接触阴影和物体之间的遮挡用来增加层次，避免靠统一深色描边制造“贴纸感”。这轮修正了水槽补片接缝和订单姓名截断；没有以整屋重画来抹掉原作者的画风。

## 八、声音：让动作和材质对应

当前库为 **41 条 CC0 外部源录音、58 个 WAV 片段、40 组音色库**，逐文件记录作者、来源、许可、剪辑参数与哈希。新增 Anthousai 的鸡蛋开壳实录，实际开壳时播放。没有新增程序合成音色，也没有提取参考游戏音轨。[完整音频说明](AUDIO.md)。

声音跟随状态：倒油、挤酱、摇盐、撒胡椒不同；水中搅动、挂酱搅动、干料翻炒与木/金属接触分层；冷锅不因放了油就无条件滋响，沸腾与干煎不会无意义地叠满。热盖泄汽、盖子接触、锅落台和真正腾空的颠锅各有触发。

本轮把停止动作时的硬切改为短淡出，保留接触后的尾音；暂停、静音和失焦仍及时停止。空瓶不继续循环，连续扫到多个切块按接触窗口聚合，避免同一动作堆几十次音效。油火会读取现有炉火录音作低量反馈，肥皂揉动复用湿搅录音；这些是音色近似，没有宣称为对应事故的现场专录。

解码、非静音、峰值、循环接缝、哈希、触发和淡出已纳入检查；**人耳逐项音色匹配与长时间混音舒适度仍单列为待验收**。

Little Chef 仍是物件交互与整体节奏主参考；Venba 是纸页与烹饪叙事参考；Cooking Simulator 是动作后果和材料反馈参考。额外研究用于校验取舍，不改变用户确定的 2D 原画方向。

### 本项目应形成的辨识点

**同一份食材贯穿整个过程，最后变成玩家自己的菜谱页。** 切得厚薄、下锅顺序、挂酱、熟度和摆盘不是结算后消失的装饰，它们可以留在实际照片与可继续编辑的纸页里。失败也能留下一次有原因的实验：把事情搞乱、理解原因、收拾，再把自己的做法写下来。

这个方向结合了物理厨房、日常顾客、手绘创作和 Solmere 的生活记录。这里不宣称全市场独创，也没有把竞品评论当成已证明的市场需求；应继续用真实玩家测试验证。

## 十一、Solmere 正式衔接

`cooking` 模块现在路由到 `scenes/restaurant_host.tscn`。厨房在独立 World2D/1600×946 视口运行，进出时保存和恢复主游戏的时步、显示与音频状态，避免两套场景互相影响。

结算使用真实出餐列表、分成与工作时长。凭据 ID 防重复领钱；保存失败回滚状态；排班按实际工作比例支付。采购仅在对应食材实际出现在已出餐料理中才消费和支付，剩余材料不自动清空。公共记录展示实际食材与顾客反馈。

菜谱和信件按旅程、存档槽、角色隔离。工程中的根目录厨房是可运行镜像，源目录为 `prototypes/100-restaurant/modules/restaurant`；同步脚本检查两份逐文件一致，CI 同时检查独立厨房和主游戏事务。

## 十二、验证、风险和下一次玩家测试

最终检查的权威记录是 QA 目录下 `checks/summary.json` 与发布 `RELEASE.json`。新增专项覆盖冷芝士不能假装完成、混合菜不能掩盖生肉、煮/融化/凉菜区间、焦面、积汽、油火与跳闸的优先级，以及提示/菜单不重叠。

其他专项覆盖缩放窗口撒粉/倒酱、锅盖附近落座、倒锅恢复、冰箱前松手遮挡、彩屑质量、泡沫退去、浮力和恢复供电；原有完整存档、DIY、刀切、温度、残味、图像、库存和音频检查保留。早期失败没有删掉断言掩盖：修正了真正的输入命中、窗口父节点访问、盖上仍可炒菜等问题；只在行为已改变时更新旧夹具假设，并保存本地失败日志。

GPU 截图检查正式纸页、陈列、锅口、切面和水流。材料对比图显式使用受控状态，便于检查融化、过热、火、泡沫是否读得清；它们不冒充自由游玩的完成录像。

早期桌面自动化曾无法取得前台窗口，后续通过明确定位本轮导出 EXE 的窗口完成了原生鼠标检查：从冰箱拿土豆、完整落刀切开、同份切片一起入锅；鸡蛋单次入锅开壳、蛋液和蛋黄受热变化；锅铲取出后留在外面并重新放回筒中。特别是原生拖放暴露了“低处入锅推走锅”的遗漏，修正后同样的鼠标路径重新通过。各次包与画面范围在最终 QA 中单独记录，不把更早包的检查冒充最新全部流程。真实 Windows IME、逐条人耳试听、长时间任意组合仍是明确的验收缺口。

建议下一次让不了解项目的玩家完成以下五件事，记录时间、误点和求助次数，**这些是待做测试，不是已经达成的指标**：

1. 不看说明找到番茄，切开并下锅；能说出柜格为何空了。
2. 撒盐后停止出料、放回原位；不会因轻转手腕丢失操作。
3. 把芝士慢慢化开，并解释锅温带与“是否化开”为什么不是同一件事。
4. 发现一次溢水或烧焦，按提示恢复；没有因物体丢失而只能重开。
5. 拍下自己的成品，改写做法、涂鸦、保存，退出后重新打开同一张页。

当前明确边界：二维水/热/色彩/压力是游戏模型；袜子与面条是软形外观加保守碰撞；不是完整 CFD、三维软体、实测化学或燃烧引擎。全部 106 种可用材料也并非每种都拥有独立录制音效、独立专属断面和独立化学反应。应围绕玩家最常用的动作持续校准，而不是以更多特效掩盖这些差距。

## 十三、最后一轮自检：复现、根因与修复

这部分专门回应“为什么玩家一玩就能发现，检查却没有发现”。检查增加了小窗口、排队输入、快速松手、暂停中途、同份多片、锅口较低落点和实际音频输出。既有测试通过不作为停止检查的理由；原生窗口发现的问题补成回归。

| 复现问题 | 根因与修复 | 检查依据 |
| --- | --- | --- |
| 鸡蛋拖进锅后没有流出蛋白蛋黄 | 改为一次有效锅口操作完成开壳；开壳中标记避免重复触发；180 ms 后分出蛋液与两半壳 | egg_cracking、quick_gestures 与导出包鼠标 |
| 暂停开壳后蛋被冻结或质量重复 | 暂停和开壳完成共用冻结状态；可食部分 88%、两半壳共 12%，总质量不变 | 单次操作、暂停恢复、质量断言 |
| 煎蛋没有明确的生熟差别 | 蛋白、蛋黄各自记录凝固进度；蛋白从透明到不透明，蛋黄继续慢慢凝固；不可逆 | 热反应、状态与画面检查 |

| 很快松手把食物丢在半路 | 保留释放目标，等待各片物理手追到；限定最长 2.2 s，避免无限悬挂 | 排队 down/move/up 输入 |

### 性能检查不能只看空厨房

在 NVIDIA RTX 4050 Laptop / Godot 4.7.2 Compatibility 下，使用 48 个真实切块（24 在菜板，24 在锅中接触），保留其他桌面应用。冷态 600 帧的中位帧耗时从初测 **135.251 ms** 降到 **27.376 ms**，P95 从 **163.1 ms** 降到 **35.633 ms**。同样场景另测 300 帧真实热演化，中位 **36.078 ms**、P95 **55.204 ms**。这些是本机本轮数据，不是最低配置或稳定 60 FPS 的承诺。

优化包含：缓存只读材质热参数；热状态改为 30 Hz 累计完整时间更新，120 Hz 碰撞和抓取不变；接触传热每对只算一次；热平衡跳过无变化工作；不反复写入相同刚体质量、惯量、阻尼、摩擦而唤醒物理对象；锅位不变时不重复设置碰撞变换；HUD 20 Hz 更新；切片用实际多边形纹理减少离屏重复渲染。

### 声音输出的证据

最终录制直接采集 Godot 混音总线，48 kHz 双声道，包含蔬菜/蛋/肉煎炒、酱泡、沸水、油/酱/盐/胡椒出料、开壳、木/金属/水中/面条翻拌、切菜、铃声和静音段。逐段检测非零信号、峰值、RMS 和零削波；窗口失焦行为另由生产回归验证。录音夹具隔离桌面切换导致的自动静音，明确标注为受控状态录音，不冒充人工听感通过。

### 仍需持续验收的部分

完整回归、有限自由操作和压力场景只能证明已覆盖路径的结果，不能证明“再也找不到任何 bug”。重负载热演化仍有帧耗时尖峰；系统输入法候选窗、听感、玩家初次理解和长时间随机混搭仍需要真实玩家验证。发行清单保留这些边界与实际已查路径，避免用一个总的“全部通过”覆盖没有做过的检查。
