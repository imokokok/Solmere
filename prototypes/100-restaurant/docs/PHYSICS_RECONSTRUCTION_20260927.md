# 物理交互重构 · 2026-09-27

本轮以用户提供的《Solmere 饭店小游戏 高精度物理引擎与物理交互重构规格书》和随后关于满锅溢水、锅盖及自然操作的反馈为依据。延续 Little Chef、Venba、Cooking Simulator 的参考分工；保留最新 main 中的手绘素材、图解菜谱、鸡蛋敲壳、固定菜板和场景清理。

## 实现

| 操作 | 当前行为 |
| --- | --- |
| 拿起食材、瓶子和锅 | 有上限的抓取力、局部抓点及手腕转矩驱动 Godot 原生刚体；重量、惯性和接触影响跟手速度。松手保留动量，不把食材冻结后跟着锅移动。 |
| 搬锅、倾倒、颠锅 | 复合空心碰撞体和真实锅沿承托独立食材；轻提、平移、放下可以保持内容物，快速横向拉扯可能滑动或甩出。颠锅音效依据真实相对腾空速度触发，声音不再给食物施加弹飞速度。 |
| 切片 | 每片保持自己的形状、质量、温度、酱汁与重力；拿起一片不再复制或冻结整批。固定菜板、刀切和原画切面保留。 |
| 木勺、锅铲 | 分别使用不同质量和接触形状，空心勺由组合碰撞体承托食物，翻拌和受热状态持续。工具松开归位仍是现有操作辅助。 |
| 接水、满锅、倾倒 | 食材占用容积，水增加锅重；超过当前低沿容量后先进入沿口余量，再沿真实锅沿位置流出。倾角、晃动改变低沿容量，移动锅不会把已流出的水瞬移走。 |
| 台面、水槽、地面 | 下落水团带有固定体积、速度及轨迹；撞击后进入水槽或台面薄层。64×8 台面格传递同一份水，水槽满后从前沿落向地面；64 个地面列由落点向两侧渐渐铺开。水槽水面随容量升高。 |
| 擦水、关水 | 海绵有限吸水，局部擦拭有体积账本；在水槽冲洗转入排水量。关水后积水按有限速率退去，避免整片蓝色直接出现/消失。 |
| 松放锅盖、长时间煮 | 0.42 kg 独立刚体靠锅沿接触支撑；沸腾与有限水汽积累产生抬升，开口持续泄汽，长期沸腾可顶起。下落和碰撞由原生求解器处理，取消必定转一圈/自动飞回架子的轨迹。 |
| 堆叠受热 | 接触锅壁也能传热；食材相互接触按成对热量交换慢慢升温。上层不会保持室温，也不会当作直接贴着锅底一样迅速焦化。未接触金属的一面按空气散热处理。 |
| 音色 | 沿用已审计外部录音；水流、煮水、滋响、倒酱、撒粉、翻拌和盖子接触读取实际状态。新增排水混音使用已有录音，没有程序合成音效。 |

取柜格的初始抓点使用按下事件的位置，避免快速排队鼠标输入已到终点时抓点偏移；只有物体实际跟到柜格附近才归库存。库存来源松手不再重复执行旧的归柜逻辑。

锅柄的取物区域也遵循前后遮挡：食材的不透明像素画在锅柄前方时，鼠标按下选择食材；食材移开后同一位置仍能拿锅，透明边缘不会挡住锅柄。

`physical_interaction.json` 集中记录抓取、锅、盖、工具及流量参数。物理步长 120 Hz、16 次求解迭代、快速物件形状 CCD。F3 检查层读取实际质量、接触、速度、温度、水量和性能；游戏界面默认隐藏它。

## 对规格书的适配及开源选择

- 使用 [Godot RigidBody2D](https://docs.godotengine.org/en/stable/classes/class_rigidbody2d.html) 的碰撞、重力、接触和休眠；保留已有 MIT GodotSpringDamper 及其固定来源、许可证。没有把第二套刚体求解器叠到原生世界上。
- [Godot Jolt](https://docs.godotengine.org/en/stable/tutorials/physics/using_jolt_physics.html) 面向三维；本项目继续使用二维手绘场景，未为引擎名称切换到 3D。Godot 商用及许可说明：[官方许可](https://godotengine.org/license/)。相关版权文本继续随工程和导出包保留。
- 文档中的数量和压力按当前画面比例校准。代码兼容字段 `pressure_pa` 是游戏压力代理，F3 明示这一点；它不是测得的帕斯卡值，也不是密闭压力锅安全模型。
- 保留用户后来明确要求的固定菜板。锅内液体、水槽深度和地面水量到屏幕高度的映射属于游戏比例；少量升水不能在现实中淹没整间厨房。

## 验证方法

完整入口仍为 `tools/run_checks.py`：45 个 Godot 回归入口，以及版本、导入、120 帧启动和逐文件录音审计。新增 `test_force_liquid_lid.gd` 覆盖动态承托、抓力上限、释放落地、有限沿口、60/120 Hz 液量守恒及锅盖升降。实际食材测试同时验证堆叠传热能量守恒。旧测试中直接搬运整批、瞬移锅、固定飞行轨迹的假设已改成与新操作一致的输入和接触断言。

首次 Linux CI 暴露的两个测试准备问题已修正：手动液量测试之后重新建立锅盖物理场景，避免冻结锅的旧求解器位置影响落盖；食材传热测试先验证真实接触，再检查两者的反向热量变化。守恒与升温断言保留，失败摘录随 QA 保存。厨房输入测试另外覆盖食材遮住锅柄和移开后的实际鼠标按下。

`capture_physical_flow.gd` 用生产模型和 GPU 渲染接水、沿口、水槽溢出、局部积水四个连续阶段。它是受控状态复现，不冒充玩家自由操作。最终完整结果及原生 Windows 窗口检查记录见 [VALIDATION.md](VALIDATION.md)。

## 近似与未完成范围

这是二维刚体、三节点传热及有限体积表面水模型，已经把力、热、颜色、材质和声音连接起来，仍不是完整 CFD、三维柔体或实验标定系统。水团不会与所有任意小道具做流固双向耦合；泡沫与蒸汽是状态驱动绘制。地面水不对所有物件求解浮力。菜板和摆盘保留透视平面约束，工具保留归位辅助。全部食材的组织断裂、专属化学变化、油水乳化和通用包装拆解尚未实现。录音审计/播放触发检查不等于人耳逐条试听。
